# 产物规范

## 选题与深度

从岗位职责和必要推断选题，不来自术语热度、参考答案篇幅或“必考”猜测；复合要求逐项承接。

每个主题要让读者能解释机制、作取舍、完成练习、定位故障。第一性原理用于解释“为何这样设计、条件变化后为何要改”，不是给定义换标题；金线先给判断，再用机制和例子支撑，删掉不能帮助理解或决策的重复。用户参考答案可借鉴主题和优先级，技术结论仍须核实。

## 目录

```text
<公司>-<岗位>-<日期>/
├── README.md                 # 学习入口
├── artifacts/
│   ├── essential.md
│   ├── qa.md
│   ├── kb/
│   │   ├── 00-roadmap.md
│   │   └── <教学章节与独立练习>
│   └── showcase/             # 项目启用时：README、实现、验证说明
└── meta/
    ├── jd.md
    ├── coverage.md
    ├── progress.md
    ├── sources/              # 按需保留原始附件
    └── resume-handoff.md     # 仅在联动简历时生成
```

`jd.md`、`coverage.md`、`progress.md` 在完整包中必需，取消项目也保留；不新增重复的 JSON 要求台账、研究日志或工具流水。教学文件真实存在，符号链接和缓存不能充当正文或实现证据。链接相对**所在文件**解析：覆盖表到教材用 `../artifacts/...`，KB 章节到 JD 用 `../../meta/jd.md`。

包入口先写岗位主线和学习优先级，再给核心、系统、实践路线，直达 Essential、KB、QA；项目和线上链接仅在存在且验收后添加。最后链接 Meta、事实差距与未完成项，不要求读者先翻运行记录。

## JD 与覆盖表

`meta/jd.md` 保存来源及访问时间、忠实提取、未知处、用户限制与采用设置。要求编号在首列且每表唯一：显式要求 `JD-*`，必要推断 `INF-*` 并写依据；P0 为核心、P1 为支撑、P2 为扩展。续作保留原编号，新增要求追加。

```markdown
| ID | 来源类型 | JD 要求/补充能力 | 优先级 |
| --- | --- | --- | --- |
| JD-001 | 明确 | 本 JD 的实际要求 | P0 |
| INF-001 | 推断 | 有依据的必要先修 | P1 |
```

`meta/coverage.md` 的 ID 集合、类型与优先级须与 JD 一致；每行对应教学、问答及实际证据或差距：

```markdown
| ID | 类型 | 优先级 | 要求 | Essential | KB | QA | 实践证据/差距 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| JD-001 | 明确 | P0 | 实际要求 | [机制](../artifacts/essential.md) | [教学](../artifacts/kb/01-topic.md) | [追问](../artifacts/qa.md) | [实现与验证](../artifacts/showcase/README.md) |
```

- 核心要求链接对应正文，尽量定位章节。支撑或扩展要求可在 Essential 列写 `非核心：具体原因`，KB、QA 仍承接；不能因难、项目未做或标成 P1 就排除关键主题。
- 学历、年限等写 `非学习项：原因`，保留真实差距与回答。实践列链接包内实际文件或有内容的真实目录，不能借符号链接引用包外证据。
- 未完成或无法证明时用 `差距：原因`、`待完成：原因与下一步`、`未验证：原因`。取消项目写 `已省略：用户取消项目`，同时提供适合的 KB 练习。
- 复合要求在同一行链接各子能力，或在表后按原 ID 简述映射；不插断表格，不重复编号。已有链接不代表内容讲够。

英文产物使用同一格式：JD 表头 `ID | Source type | JD requirement / supplemental capability | Priority`；覆盖表头 `ID | Type | Priority | Requirement | Essential | KB | QA | Practice evidence / gaps`。类型 `Explicit`/`Inferred` 不区分大小写，分别对应明确/推断；状态对应 `Non-core:`、`Non-learning item:`、`Gap:`、`Pending:`、`Unverified:`、`Omitted:`，均须具体理由。

## 四产物规范

速览：产物 → 目的 → 文件 → 验收

| 产物 | 目的 | 文件 | 验收一句话 |
| --- | --- | --- | --- |
| Essential | 时间不足时也能掌握重点、通过面试 | artifacts/essential.md | 只看它能否复述核心机制与取舍 |
| KB | 从零到原理，系统掌握岗位所需全部知识 | artifacts/kb/（含 00-roadmap.md） | 从零读者能否讲原理、迁移、排障 |
| QA | 把已学知识转成可直接演练的面试问答 | artifacts/qa.md | 短答到点、追问有推理、证据可追溯 |
| Showcase | 用实际运行、可复现的项目证明岗位能力 | artifacts/showcase/README.md | 闭环实测通过、声明可追溯、映射可查 |

### Essential：时间不足时的核心速览

**目的**：时间不足时，只看本文档也能掌握岗位核心重点、顺利通过面试；自足的速览，不是索引。

**规则**：
- 先给“必须掌握什么”的清单与阅读优先级，再逐项讲最本质的机制与取舍；
- 每项讲清：解决什么问题、输入输出与过程、为何这样设计、适用条件与失败原因；定义、类比、架构箭头不能替代机制；
- 例子给完整输入、中间状态与预期结果，可纸面推演；代码只在有助于理解时出现；
- 通用基础只补最低必要，系统先修放 KB；
- 自测改变条件、比较方案或定位故障，并给参考推理。

**验收**：读者只看本文档能否复述各核心的机制与取舍、完成自测；缺项即正文缺洞，KB/QA/项目不能补。

### KB：从零到原理的系统知识库

**目的**：从零到原理，系统掌握岗位所需全部知识，并能迁移到新条件。

**规则**：
- `00-roadmap.md` 给知识全景、主线、先修回补、章节目标、练习与晋级标准；章节依赖先修须明确链接，不循环、不隐含前提；
- 每章注明承接的 JD 要求；先讲正常流程，再用完整场景走通因果链；异步与状态变化展示关键交接与返回，不藏黑箱词；
- 按 JD 深度比较方案、选择条件与失效边界；高级要求涉及规模、可靠性与设计取舍；
- 练习覆盖跟做、变式、新输入与排障；技术练习给数据/代码/步骤、环境、运行方法、预期与验证；答案解释原因，不只列结果；
- 未被 showcase 覆盖的 JD 技术仍有教学与独立练习；模拟标明替代的角色与能证明什么。

**验收**：从零读者按路线走通后能讲原理、比方案、迁移、排障；每个 JD 主题都有对应教学。

### QA：可演练的面试问答

**目的**：把已学知识转成可直接演练的面试问答——短答先到点、追问能推理、证据可追溯。

**规则**：
- 按岗位核心主题组织，从直接问题推进到机制、约束变化、故障与方案比较；
- 每题含 `Q-001`、关联 JD、考察点、口述短答、展开推理、追问及答案、常见误区、教学链接；数量随岗位需要，不套配额；
- 短答先回应问题，深答给依据、条件与取舍；推理回到 Essential/KB 具体章节；
- 场景题给假设与验证方法；行为题只用真实经历，缺事实给待填框架，假设明确标注；
- 项目题的功能、指标、测试范围逐条核对实现或实测，不把 KB 理想设计写成项目事实。

**验收**：每题短答可直接作答、追问有推理链、教学链接指向真实章节、项目题证据对应实测。

### Showcase：可验证的能力证明

**目的**：用实际运行、可复现的项目向面试官证明岗位能力。

**规则**：
- 从岗位主线选一段业务闭环深入实现；先定输入、输出、可观察行为、验收场景与简化范围，先选证据再选技术；
- 本地运行完整链路，声明追溯到代码或实测；静态演示标明模拟范围；
- README 给业务价值、环境/依赖、启动、数据、演示步骤、预期结果、测试命令，按需写设计取舍与 JD 映射；
- 流程细节见 showcase-workflow.md。

**验收**：业务闭环与关键错误路径实测通过、可复现；每项声明可追溯；JD 映射在覆盖表逐条可查。

项目另按需要写设计取舍、验证记录与演示脚本，说明数据流、替代方案、局限、JD 映射，以及实际命令、版本、日期、结果、未测部分。非技术岗位交付有来源、方法和评价标准的可检验作品，不强加软件。

## 进度与验收

确定目录即写 `meta/progress.md`，记录输入/采用设置、当前决策、已完成文件、验证摘要、阻塞及下一步。文档、实现、项目验证、源码发布、线上演示、简历各记独立状态；未知字段不补造。源码记录仓库 URL/分支/SHA；Pages 另记实际 URL、workflow run、部署提交和浏览器结果。每阶段更新当前状态，不堆逐次工具输出。

在技能目录运行，或使用脚本绝对路径：

```sh
python3 scripts/validate_pack.py /absolute/path/to/pack
# 项目被取消时追加 --no-project；非技术作品用 --portfolio，二者互斥。
```

结构检查只验证文件、正文存在性、相对文件链接、ID、类型/优先级及映射；不验证锚点、外网链接、教学深度、代码运行或发布。技术项目至少有非文档实现文件，作品集至少有 README 之外的非空作品。内容、项目运行和发布另行验收，未完成状态在入口、进度和交付中一致说明。

## 内容验收

有独立审读者时隔离材料：Essential 只给 JD 与正文；KB 只额外给其声明的同系列先修。要求审读者指出正文依据，解释机制、推演例子变式、比较方案并定位故障；缺依据就记具体断点，不能靠审读者已有知识补齐。无独立审读者时同标准自查并说明方式。

交付前核对：复合要求是否完整、练习是否考查声明的能力、QA 是否有教学依据、项目说法是否有逐条证据；修订并复查，将内容结论记入已有进度。
