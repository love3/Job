# 双语简历

用真实经历证明与岗位的匹配度，交付事实一致、重点清楚、可阅读的中英文简历。

## 写作主线

- **第一性原理**：从岗位要解决的问题出发，确定所需能力，再选择能证明能力的经历；JD 要求不能充当本人事实，目标职位不能写成任职经历。
- **金线原理**：围绕一条能力主线组织简介、技能和经历。每句只表达一个重点，用有依据的动作、机制、结果支撑它；删去空话、重复和弱相关内容。没有实测数字就写清范围与可验证产物。
- **事实边界**：保留任职时间、贡献程度、熟练度、近似值、单位和统计口径，不自动递增年限或推导个人贡献。学习示例、QA 答案及自动生成项目不能变成履历。新项目参与未经确认时只列候选，继续用既有经历完成简历。

## 输入与设置

只读取用户提供或已加载工作区明确指定的经历、base、JD 和偏好，不从技能安装位置寻找私人资料。无 base 时直接使用真实经历；无目标岗位时生成通用版。来源冲突只核实影响结果的字段，先推进其他部分。

base 正文承载长期事实，PDF 是派生产物，不另建事实库或把额外履历藏进注释。主源由用户或工作区指定，不按语言猜测；用户明确确认优先。默认生成派生版本，只有明确要求维护 base 才原位修改；原始参考 PDF 保持只读。

新任务按“本次要求 → 已加载偏好 → 默认值”；续作先读 `changes.md` 和用户手改，已确认设置优先于后来变化的偏好。本次要求可覆盖任务设置，只有明确要求记住偏好时才保存。

## 执行

执行时读取 [输出、版式与验收](references/resume-workflow.md)；PDF 使用技能内 [渲染器](scripts/render-pdf.py) 与 [依赖清单](scripts/requirements.txt)。

1. 确认岗位版、通用版或维护 base；读取事实来源和已关联的 JD 交接。
2. 将岗位能力对应到真实证据，选定内容与输出位置。证据用来源路径和章节定位，不复制事实清单。
3. 先制作英文 HTML，渲染并验证；再制作中文，核对范围、参与程度、日期、数字和因果。
4. 两份 PDF 分别通过一页 A4、文字提取和视觉检查后，才标记成对完成。修改内容或版式后重验受影响语言。
5. 交付两种语言的 HTML/PDF、版本说明及实际检查结果；确有关联准备包时回写独立简历状态。

默认本地交付，不自动发布私人材料。简历失败不抹去已完成的面试资料，也不能把整个联动任务标成完成。
